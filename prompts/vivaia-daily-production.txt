七、真实性、来源结构与内容多样性

1. 每条日报必须能够打开，或由可靠搜索结果确认标题、来源、原始发布时间和核心事实。
搜索结果只能支持其明确展示的信息；摘要不足以支持核心事实时不入选，不靠推测补齐正文，并标明仅搜索结果核验。
官网当前活动及视觉布局必须直接核验，不能仅靠搜索摘要。

2. 不得编造标题、日期、竞品动作、销量、转化、热度或消费者结论。

3. 社媒必须定位具体帖子、视频、账号、讨论串或报告。
个别样本标“观察线索”，不能推导为普遍趋势。
尽量保留至少 2 条有价值的社媒原始内容或可信社媒研究；不足时说明，不强行占位。

4. 调查注明发布者、市场、样本、统计期及方法限制。
品牌自报数据注明性质，不能直接外推到 VIVAIA 或所有 35–55 岁女性。

5. 日报合格候选充足时，覆盖至少 4 个业务角度。
不足时说明缺口，不通过给同类内容换分类来达标。

6. 日报中：
- 单一媒体最多入选 2 条；
- Who What Wear、Marie Claire、Harper’s Bazaar 等穿搭媒体合计最多 4 条；
- 鞋型/穿搭资讯最多 2 条；
- 中文来源最多 1 条。

全篇同一品牌原则上最多 2 条独立内容，避免两个模块反复围绕同一品牌。

7. 同一主题原则上保留一条。
只有事实增量、业务问题和可参考动作确实不同，才保留两条。
不能仅因分析措辞不同就将同类事件拆成多个选题。

8. 纯 PR 默认不选，日报最多保留 1 条以新闻稿为主要依据的内容。
必须有已发生、可核验且有业务价值的实际动作。
签约、获奖、融资、愿景、普通开店或联名官宣，缺少可参考机制时排除。

9. 官网活动页、商品页和规则页属于直接证据，不因来自品牌就一律计作 PR。
品牌新闻中心按内容实质判断。

10. 环保内容全期 0–1 条。
仅保留：
- 直接影响目标市场的重大政策新进展；
- 已实际运行且能说明机制与边界的回收、维修、包装或商品举措。

政策优先监管原文，区分提案、通过、生效和执行，注明市场、对象与日期。
排除实验材料、远期承诺、联盟签约及鞋履适用性未经证实的研发故事。


八、筛选与写作

排序考虑：
事实新鲜度、证据强度、目标客群相关性、相对历史的信息增量，以及对商品、价格、活动、内容和渠道决策的价值。

能够改变选品、备货、传播或渠道判断的信息同样可以入选，不要求每条都能立即做页面实验。

日报卡片包含：
- 标题与主分类；
- 来源、原始发布时间、市场、性质标签；
- 【发生了什么】：明确的新事实；
- 【为什么值得关注】：与 VIVAIA 的商品、顾客、渠道或活动问题有什么关系；
- 【运营参考】：一个具体动作、判断或后续观察指标，区分本周可测试与中长期评估。

官网活动卡片包含：
- 标题：品牌 + 具体当期动作；
- 元信息：市场/币种、观察时间、活动阶段、日期、首次观察或实质变化；
- 【正在做什么】：真实机制、范围、门槛与限制；
- 【官网怎么承接】：已核验的入口、模块、商品组织、CTA 与路径；
- 【VIVAIA 可借鉴】：一个具体动作或判断，说明场景、人群和必要前提；
- 【证据与边界】：直接链接、未知条件、适用限制和未披露效果。

事实、推断和建议分开。
不得声称 VIVAIA 已具备未经核验的商品、会员、礼卡、履约或折扣能力。
涉及毛利、库存、赠品、配送和退换的建议，注明实施前提。
没有效果数据就写效果未披露，不把做法存在等同于有效。

文字紧凑，避免重复“提升转化”“加强内容”“舒适不累脚”等泛化建议。


九、今日重点与正式页面呈现

1. 导语不超过 80 字，提炼 5 个中文标签，每个不超过 8 字，体现本期不同信息角度。

2. Top 3 从两个模块已经入选的独立内容中选择，默认优先 2 条日报 + 1 条官网活动；没有合格官网活动时可全部来自日报。
Top 3 用于正式企微速览，必须与 latest-vivaia.json 一致，不机械取正文前三条，不添加正文没有的事实。
正式模板没有独立 Top 3 页面区块时，不为了测试版结构而新增或重排布局。

3. 使用最新一期正式 edition-*.html 和正式存档页作为模板。
保留当前正式主标题「VIVAIA 品牌趋势」、页头、字体、配色、卡片栅格、间距、按钮、响应式规则和整体布局；背景 #080c14，品牌强调色 #804c1a。
保留正式模板现有字体定义，不为本次内容优化改造字体、重写 CSS 或引入测试页样式。
移除内容中“环保至少一条”“全部近三天发布”等不再真实的旧描述，但不将文案更新扩展为视觉改版。

4. 在已有页面容器内呈现两个模块：
- 现有主卡片区域承载「今日商业日报」，最多 10 条，展示新的分类和第八节写作字段。
- 现有「竞品动态」区块改为「竞品同期官网活动」，目标 3–4 条，最多 6 条，复用该区域现有背景和排版。
- 在现有导语/说明位置写明“今日商业日报 X 条；竞品同期官网活动 Y 条”。
- 必要的采集说明放在现有说明/页脚位置。
- 最多 3 个“本周可行动”可作为现有总结区域中的简短内容，没有合适区域则融入相关卡片，不新增装饰模块或重排主布局。

各卡片通过复用现有文本块完整表达第八节字段。不要把活动再次汇总成长版竞品新闻列表；原有竞品新闻摘要由新官网活动区块替代。
正文添加稳定 id，便于行动建议链接回对应内容，但不影响既有样式。

5. 日报不足 10 条且完成规定检索时写：
“本期日报收录 X 条可核验情报，另附 Y 条竞品官网活动；完成规定检索后未以旧稿或重复内容补足。”
采集未完成时明确未完成环节，不能归因于当天没有足够资讯。
若使用近 7 天背景材料，展示条数、原始日期和“本周背景”标签，不声称全篇均为近三天新闻。

6. 正文为静态 HTML，不依赖 JavaScript 才能读取。
保留原有移动端布局；新文字和证据不得造成整页横向溢出。长 URL 使用短说明作为链接文本。
优先将截图作为现有内容块里的证据链接；若模板已有图片容器可复用，保持图片比例，不增加图库、轮播或强制加载交互。
标题和“查看来源/查看官网活动”按钮指向同一主来源，规则链接另列；外链使用 target="_blank" 与 rel="noopener noreferrer"。
保留语义化标题、可见键盘焦点和现有对比度。

7. 正式页面不得带【测试】标记，也不得照搬测试页的 robots noindex,nofollow。
不修改根目录 robots 或其他站点级 SEO 配置。

十、正式文件、期号与观察台账

1. 解析 vivaia/edition-*.html 文件名中的数字，取最大数字 +1，至少四位数字，不按文件数量计算，不覆盖历史文件。
历史目录为空时从 0001 开始；发现文件和 latest-vivaia.json 期号异常时先核查，不能猜测续号。

2. 生成 vivaia/edition-XXXX.html，保留现有正式模板。
本期完整链接：
https://baldmuzi.github.io/ai-news-daily/vivaia/edition-XXXX.html

3. vivaia/index.html 保持为往期存档，不能同步成本期全文，也不新建测试版式的 archive.html。
仅扫描 vivaia/edition-*.html，按数字期号倒序最多展示 20 期，最新高亮。
标题保持「VIVAIA 品牌趋势 · 往期存档」，保留既有样式。
本期页“返回存档”使用 ./ 或 ../vivaia/；存档页“返回首页”使用 ../。

https://baldmuzi.github.io/ai-news-daily/vivaia/
该入口是存档，不是固定全文预览页。

4. 必须用 Python json.dump 写入仓库根目录 latest-vivaia.json，保持现有正式通知兼容：

- intro：不超过 80 字。
- tags：恰好 5 个中文标签，每个不超过 8 字。

不得只提交台账或 memory.md：vivaia/** 的变化也会触发正式通知，可能发送旧日报。

十一、发布前校验

逐项检查：
- 日报与官网活动独立计数，无跨模块重复；日报 3–10 条，官网活动 0–6 条。
- 日报目标为 10 条，官网活动目标为 3–4 条；不足时有实际检索记录及具体原因，不为达标降级。
- 八组关键词、七个平台、趋势报告方向、中文来源和九个 RSS 均已尝试；访问失败和无合格候选如实记录。
- 日报不足 10 条已执行第二轮补充检索；背景最多 2 条，原始日期不超过 7 天。
- 原始日期、72 小时/本周背景标签、市场、时区和引用一致，不用转载日期伪装新鲜度。
- 官网活动有当前有效的直接依据；观察时间不等于上线时间，首次观察不伪装新增。
- 与最近 5 期正式内容去重，未使用同主题、旧稿或不同转载凑数。
- PR 最多 1 条、环保最多 1 条、鞋型/穿搭最多 2 条、中文来源最多 1 条；来源多样性和样本边界清楚。
- Top 3 是正文已入选内容，标题、分类、主来源、点评一致；标签、字数、日期、模块数量准确。
- JSON 可 json.load；edition 为数字字符串、tags 恰好 5 个、top3 恰好 3 条，各字段类型正确。
- latest-vivaia.json 的 url 指向本期正式 edition，不指向测试页或存档；三个原始来源 URL 在正文中存在。
- vivaia/index.html 仍为存档；排序、最多 20 期、最新高亮和链接正确。
- 本期页与存档页的既有 CSS 和整体布局未被测试模板覆盖；历史 edition 文件未改。
- 所引用截图存在，品牌、市场、时间、说明匹配；没有凭据、账户或个人信息。
- 用 headless 浏览器检查约 1440px 和 390px 的正文、锚点、证据链接及横向溢出，不弹出可见浏览器窗口。
- 无法完成视觉检查时明确报告限制；发现实质溢出、缺失正文或链接错误必须解决后才能发布，不能假称通过。
- git diff --check 通过；核查新增文件，确保没有临时采集日志、缓存、浏览器配置或密钥。
- 暂存范围严格符合第一节，不包含其他任务改动。

核心事实、日期、去重、Top 3、JSON、文件链接与提交范围校验失败时停止发布。

十二、提交、部署与正式通知核验

1. 只暂存本次实际生成的确切路径：
vivaia/edition-XXXX.html
vivaia/index.html
latest-vivaia.json
vivaia/memory.md
vivaia/observations.json
本期引用的 vivaia/evidence/ 图片

禁止 git add .、git add -A 或整目录盲目暂存。
再次检查 git diff --cached --name-only 与暂存差异，确认没有历史文件、共享文件、test/、report/ 或其他栏目改动。
提交消息：feat: vivaia edition #XXXX

2. 唯一允许推送：git push origin HEAD:refs/heads/main。
禁止强推。不改 remote 注入令牌。鉴权失败则报告，不能从历史提示词中复制凭据兜底。

3. 远程更新导致拒绝时，可在独立副本 fetch origin main，检查新的正式期号与当日发布状态。
若同日正式日报已由其他运行发布，或目标 edition 路径已存在，停止重复发布，不覆盖、不自动改号继续抢发。
若远程仅有无关栏目更新，可 rebase origin/main；仅无冲突、差异仍限定本期文件、校验再次通过时重试一次。
遇冲突停止并保留副本，不覆盖他人内容、不强推。

4. 确认本次 commit 位于远程 main 历史。其他任务随后改变远程 HEAD 不代表本次推送失败。
查看与该 commit 对应的 GitHub Pages 和 Notify WeCom on new edition 工作流。
确认通知本次只处理 VIVAIA，不能把其他栏目或其他 commit 的成功结果当成本期成功。

5. 如实区分现有正式脚本能力与本任务验收要求：
当前 notify.py 的 wait_for_page 主要检查 HTTP 200，超时后仍可能继续通知；它不等同于测试脚本的 HTML/JSON 严格内容匹配门禁。
不要声称现有正式链路已经做到“先校验网页内容完全一致，再发送”；本提示词也不能自行改变 CI 发送先后。
本任务仍必须独立核验发布内容，但这是发布结果核验，不是对现有脚本发送门禁的保证。
不为补足该机制擅自改 CI，也不手动重复发送。

6. 等待本次 Pages 工作流成功，并公开读回：
- 本期 vivaia/edition-XXXX.html；
- 正式存档 vivaia/index.html；
- 根目录 latest-vivaia.json；
- 本期引用的证据文件。

逐项核对本期 commit 中的内容，优先做字节/哈希比对；至少确认期号、正文、来源、模块条数、Top 3 和证据链接一致。
存档需确认包含本期，不可只检查 HTTP 200。
如存档或 latest JSON 已被后续正式版本合法替代，核验最新提交与本期历史归档分别对应，不把不同版本混作本期一致。

7. 正式通知验收使用当前脚本实际日志：
- 核实日志处理的是本次提交与本期 latest-vivaia.json；
- 查看是否有 Page ready，或明确的等待超时；
- 必须有 [VIVAIA 品牌趋势] notification sent 的成功记录，且没有对应发送失败。
当前脚本在企业微信返回 errcode=0 后输出成功记录，但不输出测试脚本的 target=WECOM_WEBHOOK_TEST; errcode=0；不得要求或伪造测试日志。

通知成功仅表示接口接受发送，不代表群成员已经阅读，也不证明网页当时内容正确。
若消息已发但网页未验证或部署失败，分别如实报告，不能重复发送兜底。

明确区分“本地生成”“推送成功”“部署成功”“公开内容匹配”“正式通知成功”。
未验证的状态不得写成功；不泄露 Webhook/token 或接口日志中的敏感内容。
